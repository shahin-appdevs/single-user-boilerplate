# Project structure blueprint

Reference for starting a new project with the same architecture, packages and conventions as `qrsim-next`. Covers structure, tooling and code patterns only — no visual design (colors, fonts, layouts, page UI).

---

## 1. Stack at a glance

| Concern | Choice |
| --- | --- |
| Framework | Next.js 16 (App Router), React 19, TypeScript 5 (strict) |
| Rendering | **Static export** (`output: "export"`) — no server runtime, all data client-side |
| Hosting | Cloudflare Workers via `@opennextjs/cloudflare` + `wrangler` |
| Styling | Tailwind CSS v4 (CSS-first `@theme`, no `tailwind.config.js`) + shadcn/ui (Radix) |
| i18n | `next-intl` v4, locale-prefixed routes, RTL support |
| Server state | TanStack Query v5 |
| Client state | Zustand v5 |
| HTTP | axios (single instance + interceptors) |
| Forms | React Hook Form + Zod v4 via `@hookform/resolvers` |
| Tables | TanStack Table v8 |
| Charts | Recharts |
| Toasts | Sonner |
| Theme switch | next-themes (`class` strategy) |
| Compiler | React Compiler (`babel-plugin-react-compiler`) |
| Node | v22 (`.node-version`) |

## 5. Layer rules (data flow)

```
page.tsx  →  features/<x>/Component  →  hooks/<role>/useX  →  services/<x>Service  →  lib/api  →  backend
                       ↓                         ↓
              lib/validators (Zod)      lib/query/keys
```

- **page.tsx** — server component. Validates locale, sets metadata via `getTranslations`, renders one feature component. No logic.
- **feature component** — `"use client"`. UI + form wiring. Calls hooks, never `apiRequest` directly.
- **hook** — wraps `useQuery` / `useMutation` with a key from `queryKeys`.
- **service** — plain object, one method per endpoint, typed with `apiRequest<T>()`. No React.
- **lib/api** — the only place touching axios.
- **store** — framework-free Zustand; callers own navigation and cache clearing.

## 6. Core patterns (copy these)

### Locale routing — `src/i18n/routing.ts`

```ts
import { defineRouting } from "next-intl/routing";

export const locales = ["en", "ar"] as const;
export type Locale = (typeof locales)[number];
export const defaultLocale: Locale = "en";
export const rtlLocales: readonly Locale[] = ["ar"];

export const isRtl = (l: Locale) => rtlLocales.includes(l);
export const isLocale = (v: string): v is Locale => (locales as readonly string[]).includes(v);

export const routing = defineRouting({ locales, defaultLocale, localePrefix: "always" });
```

`src/i18n/navigation.ts`:

```ts
import { createNavigation } from "next-intl/navigation";
import { routing } from "./routing";
export const { Link, redirect, usePathname, useRouter, getPathname } = createNavigation(routing);
```

Always import `Link`/`useRouter` from `@/i18n/navigation`, not `next/navigation`.

### Root locale layout — provider order

```tsx
export function generateStaticParams() {
  return locales.map((locale) => ({ locale }));
}

export default async function LocaleLayout({ children, params }) {
  const { locale } = await params;
  if (!isLocale(locale)) notFound();
  setRequestLocale(locale);
  const messages = await getMessages();

  return (
    <html lang={locale} dir={isRtl(locale) ? "rtl" : "ltr"} suppressHydrationWarning>
      <body>
        <NextIntlClientProvider messages={messages}>
          <ThemeProvider>
            <QueryProvider>
              <AuthBootstrapper />
              <IdleTimerProvider>{children}</IdleTimerProvider>
              <Toaster />
            </QueryProvider>
          </ThemeProvider>
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

### Thin page

```tsx
export async function generateMetadata({ params }: { params: Promise<{ locale: string }> }) {
  const { locale } = await params;
  if (!isLocale(locale)) notFound();
  const t = await getTranslations({ locale, namespace: "recipients" });
  return { title: t("metaTitle") };
}

export default function Page() {
  return <RecipientsPage />;
}
```

### Endpoints — `src/constants/api-endpoints.ts`

```ts
export const API_BASE = process.env.NEXT_PUBLIC_API_URL ?? "";

export const personalEndpoints = {
  auth: { login: "/auth/login", logout: "/auth/logout", me: "/auth/me" },
  recipients: {
    list: "/recipients",
    create: "/recipients",
    update: (id: string) => `/recipients/${id}`,
    remove: (id: string) => `/recipients/${id}`,
  },
} as const;

export const sharedEndpoints = { /* cross-role */ } as const;
```

### API client — `src/lib/api/axios.ts`

- `axios.create({ baseURL: API_BASE, timeout: 15000, headers: { Accept, Content-Type: json } })`
- Request interceptor: add `Authorization: Bearer <token>` unless `config.skipAuth`; set `Accept-Language` from `<html lang>`.
- Response interceptor: normalize via `parseAxiosError` → on 401 `clearToken()` + `emitAuthEvent("unauthorized")` (deduped by `claimUnauthorizedHandling()`, 2s window).
- `apiRequest<T>(config)` returns `response.data`.
- `apiUpload<T>(url, formData)` clears `Content-Type` so axios sets multipart boundary.
- `skipAuth` added through `declare module "axios"` merge.

### Errors — `ApiError`

```ts
type ApiError = {
  status: number; message: string; code?: string;
  fields?: Record<string, string[]>; traceId?: string;
  isNetwork: boolean; isAuth: boolean;
};
```

Backend contract assumed Laravel-style `{ message, errors, code }`. Sensitive fields (PIN) scrubbed before surfacing.

### Money mutations — idempotency

```ts
apiRequest({ method: "POST", url, data, headers: { [IDEMPOTENCY_HEADER]: newIdempotencyKey() } });
```

Writes that move money MUST set it; reads MUST NOT.

### Service

```ts
export const recipientService = {
  list: () => apiRequest<Recipient[]>({ method: "GET", url: personalEndpoints.recipients.list }),
  create: (input: RecipientInput) =>
    apiRequest<Recipient>({ method: "POST", url: personalEndpoints.recipients.create, data: input }),
};
```

### Query keys — `src/lib/query/keys.ts`

```ts
export const queryKeys = {
  shared: {
    all: ["shared"] as const,
    profile: () => [...queryKeys.shared.all, "profile"] as const,
  },
  personal: {
    all: ["personal"] as const,
    recipients: () => [...queryKeys.personal.all, "recipients"] as const,
    transactions: (f?: TxnFilters) => [...queryKeys.personal.all, "transactions", f ?? {}] as const,
  },
} as const;
```

Group per role with `.all` for bulk invalidation.

### Hook

```ts
"use client";
export function useRecipients(enabled = true) {
  return useQuery<Recipient[]>({
    queryKey: queryKeys.personal.recipients(),
    queryFn: recipientService.list,
    staleTime: 60_000,
    enabled,
  });
}
```

### QueryClient defaults

- `staleTime 30s`, `gcTime 5m`, refetch on focus/reconnect.
- Query retry: none for 401/404/422, otherwise up to 2.
- Mutations: `retry: false`.
- Global `QueryCache`/`MutationCache` `onError` → dev log (skip 401).
- `ReactQueryDevtools` only in non-production.
- `AuthEventsBridge` mounted inside `QueryClientProvider`.

### Zod validator (i18n-aware factory)

```ts
type Key = "nameRequired" | "emailInvalid";
export function createRecipientSchema(t: (k: Key) => string) {
  return z.object({
    name: z.string().trim().min(1, t("nameRequired")),
    email: z.string().trim().email(t("emailInvalid")),
  });
}
export type RecipientFormValues = z.input<ReturnType<typeof createRecipientSchema>>;
```

Used as `useForm({ resolver: zodResolver(createRecipientSchema(t)) })` with `t = useTranslations("recipients.errors")`.

## 7. Auth model (client-only)

| Piece | File | Role |
| --- | --- | --- |
| Token storage | `lib/auth/token.ts` | `remember` → localStorage else sessionStorage; keys `<prefix>.jwt` / `<prefix>.remember`; `isTokenExpired` with 30s skew |
| Store | `store/authStore.ts` | `status: unknown → authenticated \| unauthenticated`, `user`, `token`, `role`, `intendedPath`; actions `bootstrap`, `setSession`, `setUser`, `setRole`, `logout` |
| Bootstrap | `providers/AuthBootstrapper.tsx` | `bootstrap()` on mount, then `fetchQuery(me)` → `setUser` |
| Guard | `providers/AuthGuard.tsx` | skeleton on `unknown`, store `intendedPath` + redirect on `unauthenticated` |
| 401 bridge | `lib/api/auth-events.ts` + `providers/AuthEventsBridge.tsx` | interceptor emits → bridge logs out, `queryClient.clear()`, toast, redirect |
| Idle | `providers/IdleTimerProvider.tsx` + `hooks/_shared/useIdleTimer.ts` | 5 min idle, 60s warning dialog, auto logout |
| Manual logout | `hooks/user/useLogout.ts` | best-effort POST logout → store logout → clear cache → redirect |
| Roles | `types/auth.ts`, `providers/RoleRouter.tsx`, `lib/dashboard/nav.ts` | `Role` union; per-role route bases + nav |

Middleware cannot gate auth (token in browser storage, static export) — guarding is client-side only.

## 8. i18n conventions

- Messages: nested JSON per locale, one top-level namespace per feature (`common`, `nav`, `auth`, `dashboard`, `<feature>`).
- Typed via `src/types/next-intl.d.ts`:
  ```ts
  import type messages from "@/i18n/messages/en.json";
  declare module "next-intl" {
    interface AppConfig { Messages: typeof messages; Locale: import("@/i18n/routing").Locale }
  }
  ```
- Client: `useTranslations("ns")`. Server: `getTranslations({ locale, namespace })`.
- Every page / layout under `[locale]` calls `setRequestLocale(locale)` for static rendering.
- RTL: use logical Tailwind utilities only (`ms-/me-/ps-/pe-/start-/end-/text-start`), never `ml-/mr-/left-/right-/text-left`.

## 9. Styling setup (mechanism only)

`src/app/globals.css`:

```css
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn/tailwind.css";

@custom-variant dark (&:is(.dark *));

@theme inline { /* map --color-* → hsl(var(--token)) */ }
:root { /* tokens as HSL triplets: --primary: 227 100% 61%; */ }
.dark { /* dark overrides */ }
```

- Tokens stored as bare HSL triplets so backend/runtime can override at `:root`; consume as `hsl(var(--token))`.
- Dark mode = `.dark` on `<html>` via next-themes.
- `cn()` from `@/lib/utils` for class merging.
- Tailwind utilities only — no inline `style`, no extra CSS files for what a utility covers.

## 10. Naming & code conventions

- Named exports (pages/layouts excepted — Next requires default).
- Components `PascalCase.tsx`; section folders use `index.tsx`.
- Hooks `useX.ts`, services `xService.ts`, validators `<domain>.ts`.
- Feature folder layout: `Feature.tsx`, `FeatureForm.tsx`, `columns.tsx` (TanStack Table), `types.ts`, `shared.tsx`.
- `_shared/` prefix = role-agnostic; role folder (`user/`, `merchant/`…) = role-scoped.
- Import from barrels where present (`@/lib/api`).
- Minimal comments; explain *why*, not *what*.
- Never log tokens or PINs.

## 11. New-project checklist

1. Create app + install packages (section 2).
2. Copy root configs (section 3); rename worker in `wrangler.jsonc`, set `NEXT_PUBLIC_API_URL`.
3. `npx shadcn init`, add needed primitives.
4. Create `src/i18n/*`, `messages/en.json`, `types/next-intl.d.ts`.
5. Create `src/lib/api/*`, `lib/auth/token.ts`, `lib/query/keys.ts`, `lib/utils.ts`.
6. Create `constants/api-endpoints.ts`, `constants/routes.ts`.
7. Create `store/authStore.ts`, `types/auth.ts`.
8. Create providers (Theme, Query, AuthBootstrapper, AuthEventsBridge, AuthGuard, IdleTimer).
9. Build `app/[locale]/layout.tsx` with provider tree + `generateStaticParams`.
10. Add route groups `(public)`, `(auth)`, `(dashboard)/<role>`.
11. Per feature: endpoint → service → query key → hook → validator → feature component → thin page → messages.
12. Verify: `npx tsc --noEmit`, `npm run lint`, `npm run build`, `npm run preview`.
